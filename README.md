# 한국어 리뷰 클러스터링 · 합성 쇼케이스

작게 실행하고 결과를 확인하는 오프라인 예제입니다. **새로 작성한 합성 한국어 리뷰만 사용하며, 실제 고객 리뷰·작성자 정보·원본 Excel·`old data/community.zip`은 예제 입력으로 사용하지 않습니다. 전체 76.6만 건을 재실행하거나 분석 성능을 재검증한 결과가 아닙니다.**

## 한 번에 실행

Python **3.11**과 Bash가 있는 macOS/Linux에서 저장소 루트에서 실행합니다. GPU, API 키, 모델 다운로드가 필요 없습니다. 첫 실행에는 공개 Python 패키지를 설치할 인터넷 연결이 필요하며, 분석 자체는 오프라인입니다.

```bash
bash run_demo.sh
```

이 명령은 `.venv` 생성 → 고정 버전 의존성 설치 → 회귀 테스트 → 합성 분석을 실행하고 `validation/latest.txt`에 로그를 남깁니다. 다른 위치의 Python 3.11은 `PYTHON_BIN=/path/to/python3.11 bash run_demo.sh`로 지정합니다. Windows PowerShell에서는 다음 명령을 차례로 실행합니다(Windows에서는 미검증).

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python -m pip install -r requirements-demo-lock.txt
.venv\Scripts\python -m pytest -q
.venv\Scripts\python demo.py
```

결과 화면은 `artifacts/demo/index.html`, 상세 데이터는 `artifacts/demo/result.json`, 실행 로그는 `artifacts/demo/run.log`에 생성됩니다. macOS에서는 `open artifacts/demo/index.html`로 화면을 열 수 있습니다. 다시 분석할 때는 `.venv/bin/python demo.py`만 실행하면 됩니다.

## 실제 합성 샘플 결과

| 리뷰 | 분리된 절 | 긍정 / 중립 / 부정 절 | 군집 | 군집에 포함된 부정 절 | 노이즈 |
| ---: | ---: | --- | ---: | ---: | ---: |
| 16 | 31 | 16 / 2 / 13 | 3 | 12 | 1 |

군집별 4개 절이 배송 지연, 포장 파손, 누수로 묶였습니다. 선택된 대표 문장의 예는 “하지만 배송이 너무 늦었어요.”, “다만 포장 상자가 찢어져 왔어요.”, “하지만 뚜껑 틈으로 물이 새요.”입니다. “손잡이가 삐걱거리는 소음이 거슬려요.”는 노이즈로 남았습니다. 모두 이 예제를 위해 새로 작성한 문장입니다.

검증한 샘플의 [전체 JSON](examples/sample-result.json)과 [HTML 화면](examples/sample-report.html)을 함께 보관합니다. GitHub의 HTML 링크는 소스로 보일 수 있으므로 내려받아 브라우저에서 열면 됩니다. 군집 설정은 cosine 거리 `eps=0.68`, `min_samples=2`이며 예제 문구와 함께 설계한 설정입니다.

## 분석 경로와 검증 범위

`examples/synthetic_reviews.json` → 절 분리 → 전체 절에 ID 부여 → 규칙 기반 극성 판정 → 부정 절 추출 → 문자 TF-IDF 임베딩/캐시 → DBSCAN 군집 → 대표 문장 → JSON/HTML 결과 화면으로 이어집니다. 실제 파이프라인의 절 분리, ID/극성/노이즈 처리, 캐시, 대표 문장 선택 함수를 공유합니다.

이 예제의 감정 분류는 공개된 소규모 규칙, 군집은 TF-IDF/DBSCAN 기준선입니다. PyABSA, SBERT, OpenAI 임베딩, UMAP/HDBSCAN을 사용한 기존 대규모 분석의 품질을 입증하지 않습니다. 점수나 군집 수는 이 합성 입력과 설정에서의 실행 결과입니다. 리뷰 수와 절 수를 구분하고, 노이즈는 대표 군집 수에 포함하지 않습니다.

## 수정 내용

- 극성별 필터 뒤에 절 번호를 다시 매기던 문제를 수정했습니다. 절 ID는 필터 전에 부여하고, 캐시는 모델 설정과 문장 내용까지 검증합니다. 중복 ID 입력에서도 입력 순서와 행 수를 유지합니다.
- 감정값의 스칼라/리스트 형식을 처리하고 명시적 별칭을 표준 극성으로 변환합니다. 의미가 정해지지 않은 숫자 라벨을 임의의 극성으로 추정하지 않습니다.
- `-1`, `other`, 극성별 노이즈 ID를 집계·보고서·화면에서 일관되게 제외합니다. 노이즈 문장 자체는 별도로 보존합니다.
- 서로 다른 모델 공간의 벡터를 facet 계산에 혼용하는 실패 경로를 차단합니다.
- refinement 하위 군집에 충돌하지 않는 번호를 배정하고 최종 `cluster_label`과 대표 문장·키워드·보고서·영구 ID를 맞췄습니다. 원군집은 `original_cluster_label`로 보존합니다.
- 짧은 절, 반복 구두점, 실수형 군집 ID, 빈 facet, 기존 HTML 이스케이프와 상위 군집 표의 노이즈 처리도 수정했습니다.
- ABSA 재개 캐시는 입력·모델 지문과 절 순서를 확인하고 `001`, `NA` 같은 문자열 ID를 보존합니다. 영구 군집 ID는 극성별로 구분하고 번호를 순환 재사용하지 않습니다.

임베딩 캐시와 영구 군집 ID의 스키마를 v2로 변경했습니다. 과거 ID 전용 캐시는 재사용하지 않고, 기존 v1 영구 ID 상태는 경고 후 새로 계산합니다. 과거 보고서와 영구 ID가 달라질 수 있습니다. 극성당 999개 영구 ID를 소진하거나 같은 극성의 서로 다른 군집이 같은 대표 문장 서명을 가지면, 충돌하는 ID를 저장하지 않고 명시적으로 실패합니다.

통합 테스트 **86개**가 통과했습니다. 수정 전 Git 코드에 합성 입력을 넣어 오류를 재현한 근거, 수정 후 테스트, 실제 예제 결과는 [검증 기록](docs/VALIDATION.md)을 참조하세요.

## 원본 저장소와 공개 범위

Git 검토 기준은 `bglassm/wcamp_nlp`의 `08a3752898025f4d4a0747af5259ec1dc016c556`입니다. 기존 PR 작업 브랜치와 이후 `main` 변경을 확인한 뒤 최신 `main`에서 수정 브랜치를 만들었습니다. 기존 기본 브랜치의 이력을 강제로 바꾸거나 원본 파일을 삭제하지 않았습니다.

원본 저장소의 ZIP 및 이력은 [공개 적합성 감사](docs/PUBLICATION_AUDIT.md)에 기록했습니다. 별도 쇼케이스는 허용한 소스·합성 입력·검증 자료만 복사한 새 루트 커밋으로 준비하며, 원본 `.git`, 원본 데이터, 캐시, 모델, 개인 환경 파일은 가져오지 않습니다. 원본 이력을 보존한 수정 브랜치는 이 깨끗한 쇼케이스와 다릅니다.

기존 전체 파이프라인의 `main.py`와 `requirements.txt`는 검토·수정의 연속성을 위해 남겨 둡니다. 기존 설치 파일은 CUDA 등 별도 환경을 전제합니다. 재현 가능한 소규모 예제는 위의 `run_demo.sh`와 `requirements-demo-lock.txt`를 사용합니다.

## 남은 오류와 한계

- 수정한 refinement 연결은 합성 벡터와 주입한 보조 함수로 검증했습니다. 학습 모델을 포함한 전체 실행의 성공을 의미하지 않습니다.
- 전체 모델 경로의 PyABSA·SBERT·OpenAI·UMAP/HDBSCAN 통합 실행은 검증하지 않았습니다. CUDA 설치 파일을 Mac 환경에 맞게 이식한 결과도 아닙니다.
- 규칙 기반 극성은 반어·암묵적 불만·일반적인 부정 표현에 취약합니다. TF-IDF 군집과 대표 문장 선택도 정확도 평가가 아닙니다. 영구 ID의 대표 문장 기반 서명은 문구가 바뀌면 새 ID가 생길 수 있는 휴리스틱입니다.
- HTML 생성·내용 일치·입력 이스케이프는 자동 테스트했습니다. 브라우저 관리자 정책 확인 실패로 실제 렌더링의 화면 검사는 완료하지 못했습니다.
