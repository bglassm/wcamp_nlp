# Git 공개 적합성 검토

검토일: 2026-10-04. 대상: `bglassm/wcamp_nlp`. 원격에서 가져온 Git 객체를 읽기 전용으로 검사했다. 기존 Mac 작업 자료는 판정 근거로 사용하지 않았다. 원본 데이터, 개인정보 값, 커밋 작성자 연락처는 이 보고서와 로그에 옮기지 않았다.

**판정: 기존 Git 이력을 공개 쇼케이스의 기반으로 재사용하지 않는다.** 원격 `main`과 `openai`의 현재 트리에도 원문 자료 ZIP이 있으며, 과거 이력에도 남아 있다. 원본 저장소를 강제로 덮어쓰거나 이력을 재작성하지 않고, 새 Git 이력과 별도 저장소로 합성 예제를 준비하는 것이 적합하다. 파일 삭제 커밋이나 `.gitignore` 추가만으로 과거 객체가 사라지지는 않는다.

이는 셀 텍스트 내 정규식 일치 횟수이며, 중복 제거한 사람 수·확인된 연락처 수·실제 유효한 번호 수가 아니다. 제목, 본문, 요약, 원문 링크가 들어 있으므로 연락처 패턴만 제거해도 공개 적합성이 증명되지 않는다. 원문 재배포 동의, 출처별 이용 권한, 익명화의 충분성을 확인할 자료를 이 Git 이력에서 찾지 못했다. 이번에는 데이터의 진위·저작권 상태에 대한 법적 판정을 하지 않았다.

ZIP과 XLSX는 추출하거나 수정하지 않았으며, 새 예제·테스트·결과 화면에는 여기서 얻은 문장이나 개인 식별값을 사용하지 않는다. 이 36,161행 검사는 공개 적합성에 관한 구조·패턴 검사이고, 전체 약 76.6만 건 분석의 정확도를 재검증한 결과가 아니다.

## 이력의 다른 관찰

- 모든 고유 텍스트 blob에 대해 GitHub/OpenAI/AWS 토큰 형태, 개인키 헤더, 인용된 비밀번호·API 키·토큰 할당 형태, 이메일·국내 휴대전화·주민번호 형태를 검사했다. 텍스트 코드에서 인증정보 형태 일치는 0건이었다. 이것은 비밀정보가 전혀 없다는 보증이 아니다.
- 커밋 메시지의 위 패턴 일치는 0건이었다. 커밋 작성자·커미터 메타데이터에는 이메일 식별자 4개가 있고 그중 `noreply`가 아닌 식별자 1개가 있었다. 값은 기록하지 않았다.
- 전체 경로 이력에서 `LICENSE`, `COPYING`, `NOTICE`, `README` 계열 파일을 찾지 못했다. 코드나 데이터의 공개 재사용 허가가 자동으로 확인되지는 않는다. 새 저장소에는 소스 출처를 명시하고 확인되지 않은 권리를 임의로 부여하지 않는다.
- 가져온 blob 중 Git LFS 포인터는 없었다. 원격 LFS 저장소를 따로 조사한 것은 아니다.

## 범위의 한계와 공개 후보 조건

도달 가능한 가져온 브랜치와 PR 1 ref의 전체 이력을 검사한 결과다. 삭제되어 가져올 수 없는 원격 ref, 공개 목록에 없어서 가져오지 못한 다른 ref, 다른 사람의 포크, GitHub 캐시, 릴리스 첨부물, 이슈·PR 본문·댓글, 원격 reflog, 별도 LFS 저장소, 외부 원본 데이터는 검사하지 않았다. Git 객체를 삭제하거나 원격에 수정 내용을 전송하지 않았다.

깨끗한 후보에는 검토한 코드만 선별하여 복사하고, `.git`, `old data/`, 원본 ZIP/XLSX, `codex.patch`, 캐시, 원본 결과물, 작성자 연락처를 복사하지 않는다. 합성 문장을 새로 작성하고 원본 문장과 중복되지 않았다는 통계적 보증 대신 제작 경위를 명시한다. 라이선스는 권한이 확인된 범위에서만 정한다. 공개 전 후보의 파일 목록과 전체 새 이력을 별도로 검사한다.

집계 근거: `docs/publication-audit.json`. 감사 스크립트 `audit_git.py`는 원본 검토용 작업 자료에 별도로 보관했다. 스크립트는 Git 객체와 메모리 내 ZIP/XML만 읽으며, 스키마와 집계값만 JSON으로 출력한다.

## 새 저장소로 선별할 코드

`08a3752898025f4d4a0747af5259ec1dc016c556`의 `.py` 및 `rules/*.yml` 35개 파일을 별도로 검사했다. `old data/`, `codex.patch`, PowerShell 파일은 이 선별 범위에서 제외했다. Python 코드는 UTF-8 BOM을 허용해 AST로 검사했다. 연락처·인증정보 패턴, 사용자 홈/Windows/네트워크 절대 경로, 저작권 표식은 발견하지 못했다. URL 문자열은 API 엔드포인트였다. 파일별 검사 위치는 `code-allowlist-audit.json`에 기록했다.

한글 12자 이상인 Python 문자열 후보는 함수 설명 문자열과 결과 화면의 HTML 문구였다. 검토한 코드에서 원본 게시글을 담은 레코드 묶음을 발견하지 못했다. 다만 짧은 키워드·규칙·주석 문구가 어떻게 작성되었는지, 타사 코드가 섞였는지까지 증명하는 검사는 아니다. 해당 코드는 출처와 라이선스 미확인 상태를 명시한 검토용 후보로 선별할 수 있다. 원본 문장 예제는 복사하지 않으며, 새 합성 입력과 그 생성 결과만 공개 예제로 삼는다.
